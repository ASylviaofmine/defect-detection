## 二、五个转折点

格式统一为：**我原来以为 → 实测发现 → 于是改了什么**。

### 1. 为什么先做传统 CV，而不是直接上 YOLO

- 以为：传统方法就是不行，直接用现成的更好
- 实测：同一张缺陷图、同一个 Canny 阈值，**裂纹吃掉 38% 的像素，夹杂只响应 0.6%** —— 差两个数量级
- 改了：结论从「传统方法不行」改成「**传统方法需要为每一类单独调参，无法泛化**」。这个说法区别很大：前者是断言，后者是测量结果

`→ 文书可用`：*Rather than asserting that classical vision "does not work", I measured it. Under one Canny threshold, crazing floods 38 % of the frame while inclusion responds to only 0.6 % of pixels.*

### 2. 数据集不是我以为的样子

- 以为：NEU-DET 是「一张图一个缺陷」，那么任务就是单目标定位
- 实测：**每图平均 2.33 个框、最多 9 个，只有 483 张（27%）是单框**；而且图层面六类各 300 张很均衡，**框层面 inclusion 922 vs pitted_surface 386，差 2.4 倍**
- 改了：任务重新定义为**多实例检测**；看结果时不再只看 mAP，而要看每类 AP 和混淆矩阵

`→ 文书可用`：*The dataset looked balanced by image count but was imbalanced by annotation count — a distinction that only appears if you measure it.*

### 3. 最差那一类，是「漏」不是「认错」

- 以为：crazing 的 AP 只有 0.464，大概是模型把它和 scratches 搞混了
- 实测：读混淆矩阵 + 查 ultralytics 源码，发现**类别之间几乎不混（格子全 ≤0.01），错误全落在「预测成背景」那一行** —— crazing 漏检率 51%，召回只有 0.49，**是漏检，不是分类错误**
- 改了：诊断换方向，解法从「换更强的分类头」变成「救小目标」。这也直接决定了下一个转折点

### 4. 两个假设，一个被证实、一个被证伪

- 做法：诊断给出两个候选解，**一次只改一个变量，各跑 100 轮，跑之前先写下假设、代价、要看哪个指标**
- 证实：`yolov8s`（更大骨干）→ crazing AP **0.464 → 0.548**，全类 mAP50 0.758 → 0.766；代价是训练时间 ×2、参数量 ×3.7
- 证伪：`yolov8n` @960（更高分辨率）→ crazing AP **0.464，一位小数都没动**，召回反而掉到 0.247
- 为什么：**原图就是 200×200**。插值到 960 只是把同样的信息摊得更开，不增加任何真实细节

`→ 文书可用`（这是全篇最有力的一句）：*I wrote down the hypothesis, the cost and the metric before each run, so a negative result would still be informative — and one of my two hypotheses was wrong: raising resolution changed the worst-class AP by 0.000, because 200×200 source images contain no detail to recover.*

### 5. 换大模型不是全面变好，是交换

- 以为：更强的模型什么都更强
- 实测：scratches −0.057、rolled-in_scale −0.050、patches −0.027，换来 crazing +0.084、inclusion +0.070，**全类净 +0.013**
- 改了：这是个**主动的取舍**，要在 README 里写清楚换到了什么、付出了什么，而不是只报涨的那个数

## 三、我做错的三件事（共同点由我总结）

1. **把启动开销当常态，估算错了 7 倍**：用第 1 轮耗时外推，估出 3.3 小时，实际 **15.8 秒/轮、100 轮 26.3 分钟**。第 1 轮包含了建缓存 117 秒，那是一次性的
2. **延迟基准测反了**：第一次测出「3.0M 的小模型比 11.1M 的大模型慢 1.8 倍」，物理上不可能。原因是第一个跑的模型独吞了 CUDA 上下文和 cuDNN 自动调优的一次性开销。改成「全部加载预热 + 轮转测量」后才正常
3. **混淆矩阵读反了**：按教科书的习惯以为是「最后一列是漏检」，还写进了练习注释。后来翻 `metrics.py` 源码才发现 **X=真实、Y=预测，和教科书相反**，最后一行才是漏检率

## 五、这个项目没有证明什么

- **没有证明它能上线**：数据集只有 1800 张 200×200 的小图、六类、单一采集条件。分数是基准成绩，不是产线估计
- **没有独立测试集**：那 180 张在训练时不参与梯度更新，但每轮都用它选 best checkpoint。严格说它是 validation，不是 test —— 这一点我写进了 Limitations 第 5 条
- **没有时序信息**：单帧检测，不知道缺陷是「刚出现」还是「一直在」
- **没有边缘硬件实测**：延迟是笔记本 GPU 上的数，不是产线工控机
